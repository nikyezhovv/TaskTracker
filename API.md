Ниже представлена итоговая спецификация REST API для вашего TaskTracker. Она объединяет принципы постраничного вывода, фильтрации, работы с тегами и разделение ответственности между коллекцией и отдельным ресурсом.

### 1. Спецификация эндпоинтов

| Метод | Эндпоинт | Статус (Успех) | Описание |
| :--- | :--- | :--- | :--- |
| **GET** | `/api/tasks` | `200 OK` | Список задач с пагинацией и фильтрами |
| **POST** | `/api/tasks` | `201 Created` | Создание новой задачи |
| **GET** | `/api/tasks/{taskId}` | `200 OK` | Получение полной детализации задачи |
| **PUT** | `/api/tasks/{taskId}` | `200 OK` / `204` | Обновление данных задачи |
| **DELETE** | `/api/tasks/{taskId}` | `204 No Content` | Удаление задачи |

---

### 2. Подробное описание запросов

#### GET /api/tasks (Список)
*   **Query Params:**
    *   `page`: int (default: 1)
    *   `pageSize`: int (default: 20)
    *   `date`: string (ISO 8601)
    *   `status`: string (Todo, InProgress, Done)
    *   `priority`: string (Low, Medium, High)
    *   `tags`: string (через запятую: `?tags=Work,Study`)
*   **Response (200 OK):**
```json
{
  "items": [
    {
      "taskId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "title": "Написать отчет",
      "deadline": "2026-10-22T10:00:00Z",
      "status": "InProgress",
      "priority": "High",
      "tags": ["Работа", "ФИИТ"]
    }
  ],
  "pagination": { "currentPage": 1, "pageSize": 20, "totalItems": 150, "totalPages": 8 }
}
```

#### POST /api/tasks (Создание)
*   **Body:**
    *   `title`: string
    *   `description`: string
    *   `deadline`: string (ISO 8601)
    *   `priority`: string
    *   `tags`: string[]
*   **Response (201 Created):** Заголовок `Location: /api/tasks/{taskId}`.

#### GET /api/tasks/{taskId} (Детали задачи)
*   **Path Params:** `taskId` (Guid)
*   **Response (200 OK):**
```json
{
  "taskId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "title": "Написать отчет",
  "description": "Подробное описание задачи по предмету...",
  "deadline": "2026-10-22T10:00:00Z",
  "status": "InProgress",
  "priority": "High",
  "tags": ["Работа", "ФИИТ"]
}
```
*(404 Not Found, если ID не существует)*

#### PUT /api/tasks/{taskId} (Обновление)
*   **Path Params:** `taskId` (Guid)
*   **Body:** (поля для изменения, например: `{"status": "Done", "tags": ["Работа", "Готово"]}`)
*   **Response:** `200 OK` (с обновленным объектом) или `204 No Content`.

#### DELETE /api/tasks/{taskId} (Удаление)
*   **Path Params:** `taskId` (Guid)
*   **Response:** `204 No Content`.

---

### 3. Таблица кодов ответов (HTTP Status Codes)

| Код | Значение | Когда использовать |
| :--- | :--- | :--- |
| **200** | OK | Успешное выполнение GET/PUT. |
| **201** | Created | Успешное создание через POST. |
| **204** | No Content | Успешное удаление или обновление без возврата данных. |
| **400** | Bad Request | Ошибка валидации (неверный формат даты, пустой title). |
| **401** | Unauthorized | Отсутствует JWT-токен или он невалиден. |
| **403** | Forbidden | Пользователь пытается изменить чужую задачу. |
| **404** | Not Found | Ресурс с таким `taskId` не найден. |

### 2. API Запросы (Auth & Profile)

| Метод | Эндпоинт | Описание | Статусы |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/auth/register` | Регистрация (Email, Password, Name) | 201, 400 (валидация) |
| `POST` | `/api/auth/login` | Вход, получение Access/Refresh токенов | 200, 401 |
| `POST` | `/api/auth/refresh` | Обновление Access токена | 200, 401 |
| `POST` | `/api/auth/logout` | Инвалидация токена | 204 |
| `GET` | `/api/profile` | Получение данных текущего пользователя | 200, 401 |
| `PUT` | `/api/profile` | Обновление профиля (имя, настройки) | 200, 400 |
| `PUT` | `/api/auth/password` | Смена пароля | 200, 400 |

### API Запросы

#### 1. Получение списка (для календаря)
Используем фильтрацию по датам.
*   **Метод:** `GET /api/meetings?from=2026-10-01&to=2026-10-31`
*   **Код ответа:** `200 OK`
*   **Тело ответа:** Список объектов (краткая версия: только `id`, `title`, `startTime`, `endTime`).

#### 2. Создание встречи
*   **Метод:** `POST /api/meetings`
*   **Код ответа:** `201 Created`
*   **Тело запроса:**
```json
{
  "title": "Новая встреча",
  "startTime": "2026-10-25T10:00:00Z",
  "endTime": "2026-10-25T11:00:00Z",
  "description": "...",
  "location": "...",
  "tags": ["tag1"],
  "links": ["url1"],
  "participantIds": ["user_id_1", "user_id_2"]
}
```
*   **Логика:** Поскольку подтверждение не нужно, API создает запись, сохраняет связи в `MeetingParticipants` и сразу пушит уведомление в RabbitMQ для всех участников.

#### 3. Получение деталей встречи
*   **Метод:** `GET /api/meetings/{id}`
*   **Код ответа:** `200 OK`, `404 Not Found`

#### 4. Обновление встречи
*   **Метод:** `PUT /api/meetings/{id}`
*   **Код ответа:** `200 OK`, `400 Bad Request`
*   **Тело запроса:** Аналогично созданию (полный объект).

#### 5. Отмена встречи
*   **Метод:** `DELETE /api/meetings/{id}`
*   **Код ответа:** `204 No Content`
*   **Логика:** Удаление (или пометка как `Cancelled` в БД) и отправка события в очередь для рассылки уведомлений об отмене.

Ниже собраны все сценарии взаимодействия по **SignalR** (сокеты) с точки зрения того, какие данные летят от сервера к клиенту (всплывающие сообщения и триггеры для обновления UI). 

---

### Сценарий 1: Назначение встречи
*   **Когда срабатывает:** Организатор создал встречу и добавил участников (подтверждение не требуется).
*   **Действие на фронте:** Показать всплывающее окно (Toast) и обновить список встреч / календарь.
*   **Тело сообщения (Payload от сервера):**
```json
{
  "event": "MeetingAssigned",
  "title": "Новая встреча",
  "message": "Миша пригласил вас на встречу: Планирование спринта",
  "data": {
    "meetingId": "d3b07384-d113-4ec2-849f-1aaf15b3e6c0",
    "startTime": "2026-10-25T10:00:00Z",
    "location": "Переговорка №3"
  }
}
```

### Сценарий 2: Изменение встречи
*   **Когда срабатывает:** Организатор изменил время, место или описание существующей встречи.
*   **Действие на фронте:** Показать всплывающее уведомление и обновить конкретную встречу в календаре.
*   **Тело сообщения (Payload от сервера):**
```json
{
  "event": "MeetingUpdated",
  "title": "Изменение во встрече",
  "message": "Встреча 'Планирование спринта' была изменена организатором.",
  "data": {
    "meetingId": "d3b07384-d113-4ec2-849f-1aaf15b3e6c0",
    "newStartTime": "2026-10-25T11:00:00Z"
  }
}
```

### Сценарий 3: Отмена встречи
*   **Когда срабатывает:** Организатор удалил встречу.
*   **Действие на фронте:** Показать уведомление и удалить встречу из календаря пользователя.
*   **Тело сообщения (Payload от сервера):**
```json
{
  "event": "MeetingCancelled",
  "title": "Встреча отменена",
  "message": "Встреча 'Планирование спринта' была отменена.",
  "data": {
    "meetingId": "d3b07384-d113-4ec2-849f-1aaf15b3e6c0"
  }
}
```

### Сценарий 4: Приближение дедлайна задачи (от Worker-а)
*   **Когда срабатывает:** Фоновый Worker проверил задачи и понял, что дедлайн наступит через 15 минут.
*   **Действие на фронте:** Показать важное всплывающее уведомление (красный тост) и подсветить задачу в списке.
*   **Тело сообщения (Payload от сервера):**
```json
{
  "event": "TaskDeadlineApproaching",
  "title": "Приближается дедлайн",
  "message": "Дедлайн задачи 'Сделать дз по ОРГ' через 15 минут!",
  "data": {
    "taskId": "a1b2c3d4-e5f6-7890-abcd-ef0123456789",
    "deadline": "2026-10-25T14:30:00Z"
  }
}
```

### Сценарий 5: Общие системные уведомления / Напоминания
*   **Когда срабатывает:** Любое другое фоновое событие, требующее внимания пользователя.
*   **Действие на фронте:** Показать стандартный тост в углу экрана.
*   **Тело сообщения (Payload от сервера):**
```json
{
  "event": "SystemNotification",
  "title": "Напоминание",
  "message": "Не забудьте проверить выполненные задачи за сегодня.",
  "data": {}
}
```
